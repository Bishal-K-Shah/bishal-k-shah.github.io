## The Perfect Media Stack: How It All Works Together

Jellyfin alone is great. But pair it with Radarr, Sonarr, and Prowlarr? You've built something that makes Netflix's recommendation algorithm look like a TI-83 calculator.

### What Each Component Does

**Jellyfin** - Your Personal Netflix (But Better)
- Streams media to all your devices (TV, phone, tablets, browsers)
- Automatically transcodes video for different clients and internet speeds
- Manages user accounts with granular library access controls
- Handles metadata, artwork, and that satisfying search-and-play experience

**Radarr** - Your Movie Hunter
- You add a movie to your watchlist. Radarr monitors the internet 24/7 for new releases, re-encodes, quality upgrades.
- Automatically downloads it when the best quality version appears
- Renames and organizes the file perfectly
- Notifies Jellyfin, and boom—it's in your library instantly

**Sonarr** - Your TV Show Obsession Automator
- Same thing but for TV shows. Every single episode.
- Monitors release patterns (does your show usually drop Mondays?)
- Downloads the episode, renames it with proper season/episode numbering
- Handles season packs and episode upgrades
- Works even if a show goes on hiatus and returns—it remembers

**Prowlarr** - The Index Manager You've Always Needed
- Instead of configuring the same 50 movie databases in Radarr AND Sonarr, you do it once in Prowlarr
- Centralized management for all your torrent and Usenet indexers
- Tests connections, manages API keys, handles blacklists
- Radarr and Sonarr connect to Prowlarr (not directly to indexers)
- Add a new indexer? Boom. Both apps instantly have access.

**qBittorrent / Transmission** - Download Orchestrator
- Actually downloads the files when Radarr/Sonarr send jobs
- Seedbox-friendly (can run on separate server)
- Integrates with Arr apps for automatic importing and cleanup

This migration is easier than you'd think, but half-measures lead to chaos. Do this checklist right:

1. **Export what matters.** Use tools like `plex-export` to document your library structure. Note the folder organization, user accounts, and any custom collections or watch lists.

2. **Screenshot your setup.** Take photos of your current server, networking setup, and port configurations. You'll reference these.

- **Network:** Running on WiFi? Stop. Your server needs ethernet. Seriously. Lag = buffering = angry family.

## Installing Jellyfin: The Two Paths

You have options. Pick the one that doesn't make your eyes glaze over.

### Docker (The Smart Choice)

Docker handles everything—dependencies, updates, backups, even clean removal. If you're running other services (Radarr, Sonarr, etc.), Docker is non-negotiable.

**Create a `docker-compose.yml` file:**

```yaml
version: '3.8'

services:
  jellyfin:
    image: jellyfin/jellyfin:latest
    container_name: jellyfin
    restart: unless-stopped
    
    # Access Jellyfin on these ports
    ports:
      - "8096:8096"        # HTTP
      - "8920:8920"        # HTTPS
    
    # Map these folders so Jellyfin can see your media
    volumes:
      - ./jellyfin/config:/config           # Settings & metadata
      - ./jellyfin/cache:/cache             # Temporary files
      - /path/to/movies:/data/movies:ro     # Read-only movie folder
      - /path/to/tv:/data/tv:ro             # Read-only TV folder
      - /path/to/music:/data/music:ro       # Optional music
    
    # Tell Jellyfin how to reach itself from the internet
    environment:
      - JELLYFIN_PublishedServerUrl=http://your-domain.com
    
    # GPU support (uncomment for hardware transcoding)
    # devices:
    #   - /dev/dri:/dev/dri    # Intel/AMD GPU
    
    networks:
      - media-network

networks:
  media-network:
    driver: bridge
```

**Start it:**

```bash
docker-compose up -d
```

**Access it:** Open `http://localhost:8096` and complete the setup wizard. Takes 2 minutes.

### Native Installation (Linux/Windows/macOS)

**Linux (Ubuntu/Debian):**


## Hardware Transcoding: Why It Matters (And How to Enable It)

Here's the deal: If someone watches a 4K movie on their phone while your wife streams 1080p on the TV and your kid watches 720p on a tablet, **your CPU will melt without hardware transcoding.**

Hardware transcoding offloads the heavy lifting to your GPU, letting you handle 5+ simultaneous streams without sweating. Here's how to set it up:

### Intel Quick Sync (Integrated Graphics)

Nearly every Intel CPU from the last 10 years has Quick Sync. Free performance boost.

**In Docker:**

```yaml
devices:
  - /dev/dri:/dev/dri
```

**In Jellyfin:**
1. Dashboard → Playback → Transcoding
2. Enable "Hardware acceleration"
3. Select "Video Acceleration API (VAAPI)"

Test it: Play a 4K video. Check Dashboard → Sessions → Active encodings. You should see `[hw]` in the codec name.

### NVIDIA GPU (The Power User Option)

If you have an NVIDIA GPU, you get the best transcoding performance available.

**Install NVIDIA Container Toolkit:**

```bash
distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
curl -s -L https://nvidia.github.io/nvidia-docker/gpgkey | sudo apt-key add -
curl -s -L https://nvidia.github.io/nvidia-docker/$distribution/nvidia-docker.list | sudo tee /etc/apt/sources.list.d/nvidia-docker.list

sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo systemctl restart docker
```

**In Docker Compose:**

```yaml
services:
  jellyfin:
    # ... existing config
    runtime: nvidia
    environment:
      - NVIDIA_VISIBLE_DEVICES=all
```

**In Jellyfin:**
1. Dashboard → Playback → Transcoding
2. Enable "Hardware acceleration"
3. Select "NVIDIA NVENC"

### AMD Radeon GPU

AMD users get VAAPI support (same as Intel):

```yaml
devices:
  - /dev/dri:/dev/dri
```

Then select VAAPI in Jellyfin settings.

![Dashboard showing active transcoding sessions with hardware acceleration stats](https://www.rapidseedbox.com/wp-content/uploads/Jellyfin_Transcoding-8-1024x594.png)

### Verify It's Working

1. Play a video in a weird format (something your client won't support natively)
2. Go to Dashboard → Sessions → Active encodings
3. Look for `[hw]` or your GPU name in the codec. If it's missing, something's wrong.
4. Monitor CPU usage. It should be minimal. If CPU spikes, troubleshoot your GPU setup.

## Secure Remote Access (Do This Right)

Want to watch your library from work? Coffee shop? Your parents' house? You need remote access. Here's how to do it safely.

### Option 1: Reverse Proxy with Nginx (Recommended)

A reverse proxy sits between your server and the internet. Requests come in, the proxy forwards them to Jellyfin, and responses go back out. It's secure and your actual server stays hidden.

**Basic Nginx config:**

```nginx
server {
    listen 443 ssl http2;
    server_name jellyfin.yourdomain.com;

    # SSL certificates (get free ones from Let's Encrypt)
    ssl_certificate /etc/letsencrypt/live/jellyfin.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/jellyfin.yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://localhost:8096;
        proxy_http_version 1.1;
        
        # Keep connections alive
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        
        # Pass client info to Jellyfin
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**What this does:**
- Encrypts all traffic with SSL/TLS
- Hides your actual IP/server
- Jellyfin thinks requests are coming from the proxy

### Option 2: Traefik (If You're Already Using It)

Running Traefik for other services? Add Jellyfin easily:

```yaml
services:
  jellyfin:
    # ... existing Jellyfin config
    labels:
      - "traefik.enable=true"
      - "traefik.http.routers.jellyfin.rule=Host(`jellyfin.yourdomain.com`)"
      - "traefik.http.routers.jellyfin.entrypoints=websecure"
      - "traefik.http.routers.jellyfin.tls.certresolver=letsencrypt"
      - "traefik.http.services.jellyfin.loadbalancer.server.port=8096"
```

Traefik handles SSL, proxying, everything. Just deploy.

### Jellyfin's Built-In Remote Access (Not Recommended)

Jellyfin has a built-in remote access feature, but it routes traffic through Jellyfin's servers. This means:
- Jellyfin sees your traffic (privacy concern)
- Jellyfin becomes a single point of failure
- Less control over security

Use the reverse proxy approach. You'll sleep better.

![Diagram showing secure remote access architecture with reverse proxy](https://www.rapidseedbox.com/wp-content/uploads/reverse-proxy-architecture.jpg)

### Security Checklist

Before exposing Jellyfin to the internet:

- [ ] SSL certificate installed (HTTPS only, no HTTP)
- [ ] Jellyfin behind reverse proxy (never exposed directly)
- [ ] Strong passwords set for all user accounts
- [ ] Admin account changed from default
- [ ] Firewall configured (only necessary ports open)
- [ ] Fail2ban or rate limiting enabled (prevents brute force)
- [ ] Regular Jellyfin backups configured
- [ ] VPN alternative considered (more secure than remote access)

1. You download a movie in 720p
2. Later, 1080p releases
3. Set Radarr to "Upgrade until Quality X"
4. Radarr automatically downloads 1080p, replaces 720p
5. You never manually manage it

This is the power of the system. Passive library building.

## Performance Tuning: Keeping Everything Smooth

A media stack is only as good as its performance. Here's how to keep things snappy:

### Transcoding Optimization

**Hardware acceleration first:** This is non-negotiable. CPU transcoding tanks performance.

```yaml
# In docker-compose.yml, verify you have GPU access
devices:
  - /dev/dri:/dev/dri  # For Intel/AMD
```

**Concurrent stream limits:**
- Monitor your CPU/GPU usage during playback
- Set Dashboard → Transcoding → Concurrent encoders to a safe limit
- 2-3 concurrent 1080p streams = CPU burden
- With GPU: 5+ concurrent streams no problem

**Quality balancing:**
- Don't force 4K transcoding (kills performance)
- Set bitrate limits for remote clients (save bandwidth)
- Allow direct play when formats match

### Storage Optimization

**SSD considerations:**
- Put Jellyfin config + cache on SSD (faster metadata/scanning)
- Media can live on HDD (it's slower but fine for streaming)
- Cache should be 50-100GB minimum for fast metadata

**Automatic cleanup:**
- Enable automatic transcoding cleanup (deletes old temp files)
- Set library scanning intervals (avoid constant scanning)
- Archive old Radarr/Sonarr logs

### Network Optimization

**Local access:**
- Use wired ethernet for the server (WiFi = inconsistent throughput)
- Wired clients perform better too, but WiFi clients are fine if bandwidth is available

**Remote access:**
- Limit concurrent remote streams (bandwidth limited)
- Set lower bitrate for remote users (adaptive)
- Monitor your upload speed (that's your actual bottleneck)

![Performance monitoring dashboard showing CPU, GPU, and network stats](https://raw.githubusercontent.com/utkuozdemir/nvidia_gpu_exporter/master/grafana/dashboard.png)

### Database Maintenance

Jellyfin's metadata database grows over time:

1. Dashboard → Scheduled Tasks → Library optimization (run weekly)
2. Prune unused metadata cache monthly
3. Backup your database regularly (critical!)

```bash
# Simple backup
docker cp jellyfin:/config/data ./jellyfin-backup-$(date +%Y%m%d)
```

## Troubleshooting: When Things Break (And Fixes)

### Jellyfin Not Showing New Media

**Problem:** You added movies but Jellyfin doesn't see them.

**Solutions:**
1. **Manual scan:** Dashboard → Libraries → Click the three dots → Scan Library
2. **Check file paths:** Verify paths in docker-compose.yml match actual folders
3. **Check permissions:** The Jellyfin container needs read access. Fix with:
   ```bash
   chmod -R 755 /path/to/media
   ```
4. **Review logs:** `docker logs jellyfin` for specific errors
5. **Restart Jellyfin:** Sometimes a restart fixes everything
   ```bash
   docker-compose restart jellyfin
   ```

### Transcoding Failures (Pixelated/Stuttering Video)

**Problem:** Playback stutters or looks terrible when transcoding.

**Solutions:**
1. **Verify hardware acceleration is active:**
   - Dashboard → Sessions → Play a video
   - Check Active Encodings tab
   - Should show `[hw]` or GPU name (not just `h264`)
2. **Check GPU drivers:**
   ```bash
   # For Intel
   lspci | grep -i graphics
   
   # For NVIDIA
   nvidia-smi  # Should show GPU memory usage
   ```
3. **Reduce concurrent streams:** Transcoding too many at once?
4. **Lower bitrate limits:** Dashboard → Playback → Bitrate caps
5. **Test with software transcoding:** Sometimes the GPU driver is broken

### Arr Apps Not Talking to Each Other

**Problem:** Radarr can't reach qBittorrent or Prowlarr.

**Solutions:**
1. **Check Docker network:**
   ```bash
   docker network ls
   docker network inspect media-network
   ```
   All containers should be on same network.

2. **Verify API keys:** Settings → API Key in each app
   - Prowlarr API Key: Settings → General → Security
   - Jellyfin API Key: Dashboard → Users → Edit user → API

3. **Test connections:**
   - Radarr: Settings → Indexers → Test Prowlarr
   - Radarr: Settings → Download Clients → Test qBittorrent
   - Should see green checkmarks

4. **Review logs:**
   ```bash
   docker logs radarr
   docker logs sonarr
   docker logs prowlarr
   ```
   Error messages tell you exactly what's wrong.

5. **Restart everything:**
   ```bash
   docker-compose restart
   ```
   Sometimes services initialize in wrong order.

### Library Not Updating After New Downloads

**Problem:** Radarr downloads file but Jellyfin doesn't see it.

**Solutions:**
1. **Check file was moved correctly:**
   ```bash
   ls -la /path/to/movies/
   ```
   File should be there with correct permissions.

2. **Verify Radarr notification:**
   - Radarr: Settings → Connect → Check Jellyfin connection
   - Test the connection

3. **Manual Jellyfin scan:**
   - Dashboard → Libraries → Click three dots → Scan

4. **Check Jellyfin logs:**
   ```bash
   docker logs jellyfin | tail -50
   ```

5. **Restart Jellyfin:**
   ```bash
   docker-compose restart jellyfin
   ```

### Remote Access Not Working

**Problem:** Can't access Jellyfin from outside your home network.

**Solutions:**
1. **Test local access first:**
   - Confirm it works on local network
   - If not, problem isn't remote access

2. **Check firewall:**
   ```bash
   sudo ufw status
   sudo ufw allow 8096  # If using ufw
   ```
   Port 8096 must be accessible.

3. **Port forwarding:**
   - Router settings → Port forwarding
   - Forward external port 443 → server:8096
   - Use HTTPS (Port 443) not HTTP

4. **Reverse proxy working?**
   ```bash
   curl http://localhost:8096  # Local test
   curl https://jellyfin.yourdomain.com  # Remote test
   ```

5. **SSL certificate valid?**
   ```bash
   openssl s_client -connect jellyfin.yourdomain.com:443
   ```
   Check expiration date.

### Generic Debugging Process

When something breaks:

1. **Check the logs:** `docker logs [container-name]`
2. **Verify connectivity:** Ping between containers
3. **Test manually:** Try operations without automation
4. **Restart services:** Often clears temporary issues
5. **Check recent changes:** What did you change last?
6. **Community search:** Someone's had your problem before

**Pro tip:** Keep a simple test file to verify each component works:
- Test Jellyfin playback locally
- Test Radarr search manually
- Test qBittorrent with a small torrent
- Test Prowlarr indexer connections

If these individual pieces work, the problem is integration.

## FAQ: Questions People Actually Ask

### "Isn't this illegal?"

Short answer: Using Radarr/Sonarr itself is legal. What you download is your responsibility. I can't advise on that. Many people use legitimate sources (legal streaming captures, purchased files, personal backups). Many don't. Do your own research on local laws.

### "How much disk space do I need?"

Depends on your habits:
- **Small library (100 movies):** 500 GB
- **Medium library (500 movies + 10 shows):** 2-4 TB
- **Large library (1000+ movies + extensive shows):** 8-20 TB
- **4K enthusiast:** Multiply by 3-4x

Pro tip: Radarr/Sonarr can auto-upgrade to 4K and delete the 1080p version. Budget accordingly.

### "Can I share my Jellyfin with friends?"

Technically yes. But:
- Each friend needs a user account
- They use bandwidth (kills performance)
- Legal/licensing questions if sharing content
- ISP terms of service might prohibit it

Keep it within immediate family. It's more reliable that way.

### "What if Jellyfin gets hacked?"

Since it runs locally, it's way more secure than Plex. Your data doesn't leave your house unless you expose it to the internet (reverse proxy minimizes this risk). Keep Jellyfin updated and use a reverse proxy instead of exposing directly.

### "How much does this cost to run?"

After initial setup:
- **Hardware:** Already have a server? Free. New mini-PC? $200-500
- **Electricity:** ~$10-50/month depending on server
- **Subscriptions:** $0. Really. Zero.
- **Indexers:** Some are free, premium indexers are $5-20/month (optional)

Compare that to 4 streaming services at $15/month each. You break even in a month.

### "How fast can I set this up?"

**With experience:** 2-3 hours.
**First time:** Plan for a weekend.
**Time breakdown:**
- Docker setup: 30 min
- Jellyfin config: 45 min
- Arr suite setup: 1-2 hours
- Testing/optimization: 1 hour

### "What if my family doesn't understand technology?"

Jellyfin interfaces aren't as polished as Netflix, but they're not hard. Family members just need to:
1. Open Jellyfin on their device
2. Search for a movie/show
3. Hit play

Most people figure it out in 5 minutes. The magic is that everything else happens automatically.

### "Can I run this on a Raspberry Pi?"

**Pi 4/5:** Yes, but struggling. Small libraries only. No 4K transcoding.
**Pi + NAS:** Better approach. Pi for Jellyfin/Arrs, external NAS for storage.
**Mini-PC (N100):** Better option. ~$100-200, way more powerful.

Jellyfin loves powerful hardware. Don't cheap out here.

### "What about subtitles?"

Jellyfin auto-fetches subtitles for most movies (TheSubDB, OpenSubtitles). Radarr/Sonarr download subs alongside media. Configure language preferences in library settings.

### "How do I backup my setup?"

```bash
# Backup entire Jellyfin config (do this regularly!)
docker cp jellyfin:/config ./jellyfin-backup-$(date +%Y%m%d)

# Or add to cron for weekly backups
0 2 * * 0 docker cp jellyfin:/config /backups/jellyfin-$(date +\%Y\%m\%d)
```

Backup before updates. Your database is precious.
